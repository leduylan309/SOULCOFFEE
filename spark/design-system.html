    SCSS & component API

    Source lives in scss/: abstracts → base (tokens, reset, typography) → layout → components (one file each) → sections (page-specific) → utilities. Build with npx sass scss/main.scss css/main.css.

    Component ruleEvery component styles only its own classes and depends only on tokens. Drop it into any page or section and it renders the same.
    Customising from outsideParents never restyle a child. They set the child's public custom properties, or only position it (margin and alignment).

    UX/UI standards

    Full list in UX-UI-STANDARDS.md. Key do / don't:

    DoOne H2 per section, purple. Alternate ivory / ivory-2 backgrounds. Fixed image ratios. Cards equal height, CTA at bottom. Hit targets ≥ 44px. text-wrap:balance on titles.
    Don'tHard line breaks in titles. Long copy beside a small image. Cards touching the next section. Two primary buttons side by side. Images hotlinked from outside site-v2.
    DoLong stage content → vertical roadmap. Parallel content → tabs. Long guides → summary box first.
    Don'tTall narrow columns of text (5-up cards with paragraphs). Forms longer than one screen.
